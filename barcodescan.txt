# NutriMatrix — Barcode Product Detection + Open Food Facts + Expiry Detection + Digital Pantry

Implement the following complete feature in the existing **NutriMatrix** project.

The goal is to identify products dynamically using **Open Food Facts**, detect the expiry date from an uploaded/scanned image using **OpenCV + Tesseract OCR**, and then add the verified item to the user's **Digital Pantry**.

# 5. IMPORTANT COUNTRY FILTER BEHAVIOR

This distinction is critical.

## Product-name search

When the user selects:

```text
Country = India
```

and searches:

```text
Product = Milk
```

the Flask backend should pass the country information to the Open Food Facts **search/filter request**.

Conceptually:

```text
Country = India
Product = Milk
       ↓
Flask
       ↓
Open Food Facts search
       ↓
countries_tags_en = india
       ↓
Indian-associated matching products
```

Use the appropriate Open Food Facts country search/filter parameter documented by the API, such as:

```text
countries_tags_en=india
```

Do NOT simply show the country dropdown in the UI without actually using it in the product-name search request.

---

# 6. IMPORTANT — BARCODE LOOKUP IS DIFFERENT

Do NOT incorrectly treat the country dropdown as an India-only filter for barcode lookup.

When the user scans:

```text
8901234567890
```

the barcode itself is the primary product identifier.

The workflow is:

```text
Barcode
 ↓
Barcode Decoder
 ↓
8901234567890
 ↓
Open Food Facts product-by-code lookup
 ↓
Product information
```

The country selection should NOT be used as though it guarantees:

```text
"Search this barcode only in India"
```

because barcode lookup is an exact product-code lookup.

The country information can be used where appropriate for localization/search behavior, but the barcode itself remains the primary identifier.

This distinction must be implemented correctly.

# 7. PRODUCT DETECTION OPTIONS

Provide three product detection methods:

## OPTION 1 — Scan Barcode

Display:

```text
📷 Scan Barcode
```

When clicked:

* Request camera permission.
* Open camera.
* Detect barcode.
* Decode barcode into its numeric value.
* Display the detected barcode number.
* Send the number to Flask.
* Query Open Food Facts.
* Display the product.

---

## OPTION 2 — Enter Barcode Number

Display:

```text
Enter Barcode Number

[______________________]

[Search Product]
```

The user can type a barcode manually.

Validate:

* Not empty.
* Valid characters.
* Remove accidental spaces.
* Reject obviously invalid values.
* Never crash if the input is malformed.

Then send it to the same Flask product lookup endpoint used by barcode scanning.

Therefore:

```text
Scan Barcode
       |
       +----> barcode number
                         |
Manual Barcode ---------+
                         ↓
                  Same Flask API
                         ↓
                 Open Food Facts
```

Do NOT create separate product lookup logic for these two methods.

# 8. BARCODE IMAGE/CAMERA TECHNOLOGY

Do NOT use Tesseract OCR to read the barcode.

Barcode detection should use a dedicated barcode decoder.

Recommended technology:

```text
ZXing
```

or another reliable browser-compatible barcode decoding library.

The purpose is:

```text
Visual Barcode
      ↓
ZXing / Barcode Decoder
      ↓
Barcode Number
      ↓
Open Food Facts
```

For example:

```text
Camera
 ↓
|||| |||| || |||||
 ↓
ZXing
 ↓
8901234567890
```

The user should NOT need to manually type the number when camera scanning succeeds.


---

# 19. OCR ERROR HANDLING

OCR can incorrectly recognize characters.

For example:

```text
O → 0
I → 1
S → 5
```

The implementation should carefully normalize obvious OCR mistakes where safe.

Do NOT blindly modify every character.

If the date cannot be reliably determined:

```text
Expiry date could not be detected clearly.

Please scan again or upload a clearer image.
```

Do NOT automatically save an uncertain date.

# 23. FLASK BACKEND

Create or reuse suitable endpoints.

For barcode:

```text
POST /api/product/barcode
```

Responsibilities:

1. Receive barcode.
2. Validate barcode.
3. Call Open Food Facts.
4. Parse response.
5. Return product information.

For product-name search:

```text
GET/POST /api/product/search
```

Responsibilities:

1. Receive product name.
2. Receive selected country.
3. Apply Open Food Facts country filter.
4. Search products.
5. Return matching results.

For expiry:

```text
POST /api/expiry/detect
```

Responsibilities:

1. Receive image.
2. Validate image.
3. Process image with OpenCV.
4. Run Tesseract OCR.
5. Extract expiry date.
6. Validate date.
7. Return detected expiry date.

For pantry:

```text
POST /api/pantry
```

Responsibilities:

1. Receive confirmed product.
2. Receive confirmed expiry.
3. Associate item with logged-in user.
4. Store pantry record in MySQL.

Reuse existing endpoints if equivalent routes already exist.

# 30. FINAL EXPECTED USER EXPERIENCE

A user should be able to do this without manually entering product information:

```text
1. Open Scanner
        ↓
2. India is selected
        ↓
3. Scan barcode
        ↓
4. Barcode automatically becomes a number
        ↓
5. Open Food Facts finds the product
        ↓
6. Product information appears
        ↓
7. User scans expiry OR uploads expiry image
        ↓
8. OpenCV processes image
        ↓
9. Tesseract detects expiry text
        ↓
10. System extracts expiry date
        ↓
11. User confirms
        ↓
12. Product + expiry added to Digital Pantry
        ↓
13. MySQL stores the user's pantry record
```

The key principle is:

**Open Food Facts handles dynamic product identification. ZXing handles barcode-to-number decoding. OpenCV + Tesseract handles expiry detection. MySQL stores the user's Digital Pantry records — not a manually maintained product database.**

Before modifying code, inspect the existing NutriMatrix implementation and integrate this feature without breaking any existing functionality or CSS.
