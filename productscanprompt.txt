# NEW PRODUCT SCAN CARD

Inside the existing scanner UI, create/modify the **Product Scan Card**.

The Product Scan Card must contain exactly **2 steps**.

### STEP 1 — FRONT PRODUCT IMAGE

Title:

**Step 1: Scan Product**

Purpose:

Capture or upload an image of the **front of the grocery product package**.

The user should have two choices:

**📷 Scan**

and

**⬆ Upload Image**

### Scan

When the user clicks Scan:

1. Open the device/browser camera.
2. Display the camera preview.
3. Allow the user to capture the front image.
4. Show the captured image preview.
5. Provide:

   * Retake
   * Use Image
6. Process the image.

### Upload Image

When the user clicks Upload Image:

1. Open the file picker.
2. Allow the user to select an existing product image.
3. Display the selected image preview.
4. Allow the user to replace the image.
5. Process the image.

The image should preferably show the **front of the product package**, because this is used for product identification.

---

# PRODUCT IMAGE DETECTION

Use appropriate image-processing and OCR technologies to identify the product.

### Technologies

Use the existing NutriMatrix technology stack wherever possible:

**Frontend**

* HTML5
* CSS3
* JavaScript

**Backend**

* Python
* Flask

**Image Processing**

* OpenCV
* NumPy
* Pillow where required

**Text Recognition**

* Tesseract OCR

**Database**

* MySQL

Do not add unnecessary paid services.

Do not require barcode APIs.

Do not require a barcode number.

---

# HOW STEP 1 SHOULD PROCESS THE IMAGE

After the user captures/uploads the front product image:

```text
Product Image
      ↓
Frontend
      ↓
Flask API
      ↓
Image Preprocessing
      ↓
OpenCV / Pillow / NumPy
      ↓
Image Enhancement
      ↓
Tesseract OCR
      ↓
Extract Visible Product Text
      ↓
Product Identification
      ↓
Search Existing MySQL Product Database
      ↓
Return Product Information
```

Image preprocessing can include, when useful:

* Resize
* Crop
* Noise reduction
* Grayscale conversion
* Contrast enhancement
* Thresholding
* Perspective correction

Do not apply unnecessary processing if the original image is already clear.

---

# PRODUCT INFORMATION

From the front product image, attempt to detect:

* Product name
* Brand name, if visible
* Product category
* Quantity/pack size, if visible

The system should use the detected product name/text to match an existing product in the NutriMatrix MySQL database.

If the product exists:

```text
Product Found ✓

Product Name: Milk
Category: Dairy
Quantity: 1 L
```

If a product cannot be confidently identified:

```text
Product could not be identified.

Please upload a clearer image of the front
of the product package.
```

Provide:

**Try Again**

and

**Upload Another Image**

Do not invent a product.

---

# STEP 2 — EXPIRY SCAN

After Step 1 successfully identifies the product, automatically move/show:

**Step 2: Scan Expiry**

Purpose:

Detect the expiry/best-before information printed anywhere on the package.

The user should again have exactly two choices:

**📷 Scan**

and

**⬆ Upload Image**

The user should NOT be required to photograph the entire product again.

They should take/upload a **close-up image of the area where the expiry information is printed**.

The expiry can be located on:

* Top
* Bottom
* Back
* Side
* Seal
* Cap
* Label
* Package edge
* Any other location

---

# EXPIRY IMAGE PROCESSING

Process the expiry image using:

**OpenCV + NumPy/Pillow + Tesseract OCR + Python/Flask**

Processing flow:

```text
Expiry Image
      ↓
Frontend
      ↓
Flask API
      ↓
Image Preprocessing
      ↓
OpenCV / NumPy / Pillow
      ↓
Tesseract OCR
      ↓
Extract Text
      ↓
Detect Date / Expiry Pattern
      ↓
Validate Date
      ↓
Return Expiry Date
```

The system should recognize common formats such as:

```text
EXP 25/10/2026
EXP: 25-10-2026
EXP 25.10.2026
EXP DATE 25/10/26
Expiry: 25/10/2026
Best Before 12 Months
```

It should also handle common variations in spacing and punctuation.

---

# IMPORTANT EXPIRY RULE

NEVER assume an expiry date.

Do not automatically assign:

* 3 days
* 5 days
* 7 days
* 30 days
* Any generic expiry period

The actual date must come from the package/OCR whenever possible.

For example:

```text
Detected:
EXP 25/10/2026

Save:
25/10/2026
```

If the package only says:

```text
Best Before 6 Months
```

do not blindly calculate the expiry date unless a reliable manufacturing/packing date is also detected.

If the required information is missing, tell the user that the expiry date could not be reliably determined.
